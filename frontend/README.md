# Фронтенд кредитного кабинета

React 18 + Vite, без UI-библиотек: компоненты и токены перенесены из дизайн-системы «Кредитный кабинет» (макеты Claude Design, `Credit Cabinet.dc.html`). Только светлая тема.

## Запуск

```bash
cd frontend
npm ci
cp .env.example .env
npm run dev            # http://localhost:5173
```

Фронтенд работает только с бэкендом: без него на экране входа будет «Нет связи с сервером». Бэкенд лежит в `backend/` и поднимается одной командой (подробности в `backend/README.md`):

```bash
cd backend
docker compose up --build -d                             # API на http://localhost:8000
docker compose exec api python -m app.infra.mocks.seed   # необязательно: тестовые учётки
```

Без seed база пустая: пользователь регистрируется сам и подаёт заявку по ИНН компании, где он руководитель по ЕГРЮЛ. Тестовые учётки и данные целиком на стороне бэкенда, во фронтенде ничего не зашито: что бы ни лежало в базе, править фронт не нужно.

## Подключение бэкенда

| Переменная | Что делает |
|---|---|
| `VITE_API_URL` | База запросов, по умолчанию `/api/v1` |
| `VITE_BACKEND_URL` | Куда dev-сервер проксирует `/api` вместе с вебсокетом (пути не переписываются). По умолчанию `http://localhost:8000` |
| `VITE_WS_URL` | Хост вебсокета (`ws://host:port`), если бэкенд на другом адресе. Пусто — тот же хост, что у `VITE_API_URL` |

Контракт — [backend/docs/API.md](../backend/docs/API.md) и OpenAPI бэкенда (`http://localhost:8000/docs`). Все запросы — в одном файле [src/api/real.js](src/api/real.js).

- Почти все запросы — `POST` с JSON-телом, идентификаторы (`application_id`, `contract_id`, `statement_id`) передаются в теле, а не в пути. Лишние поля в теле бэкенд отклоняет с 422.
- id заявок и договоров — UUID. В интерфейсе показываются первые 8 символов: «Заявка №3f2a9c1b».
- Авторизация: `Authorization: Bearer <access_token>` из `POST /auth/login`.
- Ошибки: `{ "error": { "code", "message", "details": [{ "field", "code", "message" }] } }`. `details` показываются под полями формы (`options[0].rate` и `options.0.rate` приводятся к одному виду), в формах с одним полем — первая причина из `details`. `code` нужен для особых случаев (`SOURCES_NOT_READY`).
- 401 — выход на экран входа, 0 или 5xx — полоса «Нет связи с сервером» с кнопкой «Повторить».
- Статусы: вебсокет `/api/v1/ws/applications`, токен подпротоколом `["bearer", token]`, ping раз в 25 секунд. `application.status_changed` — перечитать заявку, `application.step` — подпись шага на линии статусов. Пока сокет не подключён, заявка перечитывается раз в 3 секунды.
- Кнопки на странице заявки и договора показываются по `allowed_actions` и `allowed_operations` из ответа.
- Машинные коды (причины ручной проверки, стоп-факторы, причины переходов) показываются подписями из [src/lib/labels.js](src/lib/labels.js) (`REASON_LABELS`); новый код без подписи выводится как есть.
- Компания попадает в профиль (`UserOut.companies`) после первого `/consents/give` — после согласий фронт перечитывает профиль.

### Чего нет в API и что сделано на фронтенде

- Справочника причин отказа нет — список `reason_code` лежит в `REJECT_REASONS` ([src/lib/labels.js](src/lib/labels.js)).
- Пункты дозапроса аналитика — коды `STATEMENT` и `COLLATERAL`; клиенту по ним показывается загрузка выписки и форма залога.
- В списке договоров нет ИНН, поэтому на главной показываются все договоры пользователя.
- «Веду бизнес в этом банке» по умолчанию берётся из `has_account` в `/companies/get` (приходит только руководителю), на бэкенд не отправляется.

## Скриншоты

```bash
npm run dev
npm run shots -- login register
```

Каждый снимок делается в чистом профиле браузера, без входа, поэтому так снимаются только открытые страницы. Снимки 1440 × 900 и 360 × 800 появятся в `shots/`. Нужен Chrome или Edge, путь можно задать через `CHROME_PATH`.
