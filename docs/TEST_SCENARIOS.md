# Тестовые сценарии

**Вход:** кабинет http://localhost:8080, логин из колонки «Кто входит», **пароль у всех учёток `demo-password-2026`**.

Анкета заявки состоит из четырёх шагов: «Цель», «Условия», «Выручка», «Согласия и отправка». Ниже для каждого сценария указано, что вводить и какие кнопки нажимать. Каждый сценарий также покрыт автотестом из колонки «Тест» (`backend/tests/e2e`). Те же шаги без интерфейса есть в коллекции запросов `backend/docs/credit-conveyor.postman_collection.json`.

Данные компаний синтетические и лежат в `backend/app/infra/mocks/data`. Класс риска и баллы в ожидаемых результатах клиент не видит: в кабинете ему показываются только решение и его причины текстом, а скоринг целиком есть в отчёте аналитика (`analyst`).

## Основные сценарии

Общее для всех сценариев клиента:

- **«Цель»**: войти → «Подобрать кредит» → ввести ИНН компании, выбрать цель → «Продолжить»;
- **«Условия»**: продукт, вариант, сумма и срок из таблицы → «Продолжить»;
- **«Выручка»**: банк сам отмечает, где клиент ведёт бизнес. У всех, кроме `ivanova`, уже выбрано «Веду бизнес в этом банке», выручка считается по оборотам счёта, поэтому ничего не меняем и нажимаем «Продолжить». У `ivanova` счёта в банке нет: выбрано «Веду бизнес в другом банке», загружаем выписку (сценарий 4);
- **«Согласия и отправка»**: отметить все согласия → «Отправить заявку». На странице заявки по шагам видно, какой источник сейчас проверяется, решение приходит через несколько секунд.

## Нестандартные ситуации

| Ситуация | Как воспроизвести | Ожидаемый результат | Тест |
|---|---|---|---|
| Источник не ответил | в Swagger (http://localhost:8000/docs) войти как `analyst` и вызвать `POST /dev/mocks/failures` с `{"source": "BKI", "inn": "7714012340", "enabled": true}`; затем `kolos` подаёт заявку как в сценарии 1 | после 3 попыток «Заявку смотрит специалист». У аналитика в отчёте БКИ без ответа, одобрить нельзя. После выключения поломки (`"enabled": false`) аналитик выбирает «Повторить проверки», заявка одобряется | `test_source_unavailable.py`, `test_analyst_actions.py` |
| Дозапрос и отказ аналитика | заявка `techprom` из сценария 5 в ручной проверке → у аналитика «Запросить информацию» → «Данные залога» с пояснением; клиент дополняет залог и отправляет; аналитик «Отказать» с причиной | заявка возвращается клиенту с пунктом от аналитика, после повторной отправки снова у специалиста, затем отказ с выбранной причиной | `test_analyst_actions.py`, `tests/integration/api/test_analyst_api.py` |
| Контрпредложение аналитика | у аналитика «Контрпредложение», «Добавить вариант» с суммой и ставкой → «Отправить решение»; клиент видит варианты | клиент может взять вариант или отказаться («Да, отказаться»); выбор варианта с залогом («Оформить с залогом») возвращает заявку за данными залога | `test_analyst_actions.py` |
| Одобрение не принято 7 дней | одобренную заявку не подписывать | через 7 дней заявка отменяется сама | `test_scenario_1_kolos.py::test_approval_is_cancelled_after_7_days` |
| Эмуляция времени по договору | в договоре из сценария 1, блок «Режим разработчика — только для демо»: «Следующий месяц», затем «Погасить частично», «Перемотать до даты» на конец срока, «Сбросить демо» | платежи по графику; после частичного погашения новая версия договора и PDF с пересчитанным графиком; в конце срока договор закрыт; сброс возвращает договор к выдаче | `test_emulation.py`, `test_scenario_1_kolos.py` |
| Правка договора аналитиком | `analyst` → «Договоры» → договор → «Изменить договор»: новая ставка или срок, комментарий → «Сохранить новую версию» | версия 2 договора с новым PDF и пересчитанным графиком | `test_contract_edit.py` |
| S3 недоступен при подписании | только в автотесте | подписание откатывается, заявка остаётся на подписании, код можно ввести снова | `test_signing_storage_unavailable.py` |
| Чужие данные | только в автотесте: клиент запрашивает чужую выписку или договор | доступ запрещён (403) | `test_scenario_4_ivanova.py`, `test_emulation.py` |
| Выписка больше 10 МБ | загрузить на шаге «Выручка» файл больше 10 МБ | ошибка о размере файла, выписка не принимается | `test_scenario_4_ivanova.py` |

## Автотесты

```bash
cd backend
docker compose up -d postgres minio             # базы для integration и e2e
uv sync
uv run pytest -q                               # unit, integration и e2e
```

- `tests/unit` — правила домена без ввода-вывода: стоп-факторы, поводы ручной проверки, 10 факторов скоринга на границах, правила решения, продукты, график платежей, таблица переходов статусов;
- `tests/integration` — API на in-memory зависимостях, репозитории на PostgreSQL, хранилище на MinIO, соответствие `backend/docs/openapi.json` коду;
- `tests/e2e` — сценарии из таблиц выше целиком через HTTP и WebSocket.

Коллекцию запросов можно прогнать на поднятом стенде одной командой из корня репозитория (на чистой базе после `docker compose down -v`):

```bash
npx newman run backend/docs/credit-conveyor.postman_collection.json --working-dir .
```

Выписки сценария 4 привязаны к дате: последняя операция должна быть не старше месяца. Лежащие в репозитории файлы заканчиваются 23.10.2026; если демо идёт позже 23.11.2026, перегенерируйте их (см. README, раздел «Тестовые данные»).
